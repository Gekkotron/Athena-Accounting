# v1.0.0-desktop-rc9 — release candidate

Third desktop pre-release documented after `v1.0.0-desktop-rc1`.
Packaging and Gatekeeper story unchanged — see
[`v1.0.0-desktop-rc1`](./v1.0.0-desktop-rc1.md) for the macOS
`xattr -cr` step. This batch is a focused expansion of the import
surface: four new file formats land together — **QIF**, **MT940**,
**Excel** (`.xlsx`), and **BAI2**.

## Import surface expansion

Athena now reads every statement format a bank is realistically likely
to export. Each format plugs into the same pipeline (`inferFormat` →
`parseFile` → `ParsedTransaction[]` → dedup + categorisation + insert)
with no changes to the import orchestrator or the frontend upload
flow — only the accept list and the format table grew.

- **QIF** (Quicken Interchange Format). Bank, Credit Card, Cash, and
  Asset/Liability sections. US `MM/DD/YYYY` and European `DD/MM/YYYY`
  dates (disambiguated when `day > 12`), French comma / US
  thousands-separator amounts. Covers Quicken, GnuCash, Moneydance,
  and most legacy accounting-software exports. No bank-side unique
  id, so dedup falls back to the hash key `(account, date, amount,
  normalized label)`.
- **MT940** (SWIFT pre-ISO 20022 bank statement). `:61:` statement
  lines + `:86:` narratives with `?NN?` structured-subfield stripping,
  UTF-8 and Windows-1252 auto-decode, 2-digit years treated as 19xx
  when ≥ 80 else 20xx, bank reference from `:61:` used as the dedup
  fingerprint when present. Supports `.mt940`, `.sta`, and `.swift`
  extensions.
- **Excel** (`.xlsx`) via `exceljs`. The header row is detected
  within the first 20 rows; the same date / label / `Montant` or
  `Débit`+`Crédit` heuristic as the CSV parser applies, with French
  accented headers matched accent- and case-insensitively. Real Excel
  date cells, Excel serial numbers, and string dates are all
  recognised. **Legacy binary `.xls` (BIFF) is deliberately not
  supported** — `exceljs` only reads Open XML. Re-save as `.xlsx` in
  Excel or LibreOffice (one click). `exceljs` chosen over SheetJS to
  keep a single actively-maintained spreadsheet dependency.
- **BAI2** (US cash management, `.bai` / `.bai2`). Records
  `01`/`02`/`03`/`16`/`88` parsed. Transaction type codes 100–399 are
  credits, 400–699 are debits, else skipped (summaries and
  non-monetary records are dropped defensively). Date inherited from
  the `02` group header with the same century rule as MT940, amounts
  read in cents and converted to decimals, bank reference used as the
  dedup fingerprint.

A single Postgres migration
(`0046_import_format_qif_mt940_xlsx_bai2.sql`) extends the
`import_format` enum with the four new values. The desktop build runs
migrations on startup, so upgrading is a no-op for existing installs.

## Bug fixes

- `fix(imports)`: drop `.xls` from the Excel accept list — `exceljs`
  reads only Open XML; the legacy binary format would be accepted at
  the extension gate and fail at parse. Pulling `.xls` from
  `inferFormat`, both 400-error strings, and the frontend accept list
  keeps the surface honest. (`ce99616`)

## Deferred

- **QBO (QuickBooks Web Connect)** — OFX variant with a QuickBooks
  product tag. A thin wrapper around `parseOfx` would ship it in a
  future batch.
- **FinTS / HBCI** — German/Austrian online-banking protocol with
  session, encryption, and TAN flow. Shape is closer to Enable
  Banking's bank-sync than to a file parser, so sized as a separate
  project rather than a parser.
